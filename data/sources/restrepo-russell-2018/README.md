# Restrepo & Russell (2018) database of planar axisymmetric CR3BP periodic orbits

Source note for a dataset that is held OUTSIDE this repository, like the SPICE kernels.
Built 2026-10-07 by a one-off read-only inventory script (not kept in the repo) on the copy described below; its raw output is `inventory_raw.tsv` in this directory.

## 1. What it is

- Paper: Restrepo, R. L. and Russell, R. P. (2018), "A database of planar axisymmetric periodic orbits for the Solar system", Celestial Mechanics and Dynamical Astronomy 130:49, doi 10.1007/s10569-018-9844-6. Project digest: `docs/notes/2026-06-17-digest-restrepo-russell-2018.md`.
- Content: about 3.96 million converged planar, axisymmetric (two perpendicular x-axis crossings) periodic orbits of the circular restricted three-body problem (CR3BP), for 24 systems: 8 Sun-planet systems, Earth-Moon, 4 Galilean moons, 6 Saturnian moons (Enceladus, Tethys, Dione, Rhea, Titan, Iapetus), 4 Uranian moons (Ariel, Umbriel, Titania, Oberon) and Triton. Per system there are global searches (low resolution A, high resolution D) and local searches around LL1, LL2 and the DRO family.
- Version: the unpacked tree is `POs_database_v2019-12-28`. Inside it: data folder `POs_database_all-2017-12-14` (data posted 2017-12-12 to 2017-12-14; individual runs are dated 2015-07-07 to 2017-12-05 in their folder names), MATLAB scripts `scripts_matlab-2019-12-18`, and the licence and citation added on 2019-12-18 (README.txt revision notes). The inner archive is dated 2019-12-19.
- Location: `~/dev/references/restrepo-russell-2018/POs_database_v2019-12-28/` (read-only reference store, outside the repo). The inner archive is `~/dev/references/restrepo-russell-2018/PeriodicOrbitDatabase/POs_database_all.zip` (607,128,575 bytes, md5 03ea4d76beb3a6232aae08e7446bcbf1, measured here). Outer zip md5 as supplied by the task owner: 38dbaeab079f06a6662dae2e87c14e22 (the outer zip itself is not on disk; not re-measured).
- Where the authors publish it: paper footnotes 4 and 5, on printed page 20 of 24 (page 49:20 of the journal pagination; section 5 "Online database structure"): http://russell.ae.utexas.edu/index_files/POdatabase.htm and https://drive.google.com/drive/u/1/folders/0B7SdUc9xp3V6VTRGbmwzQ1lzSFE . (The task text said p.22; the footnotes are on p.20.) I did not check whether these URLs are still live.
- Size check against the paper (p.20-21): "approximately 3 GB (600 MB compressed)". Measured: 189 data files, 3,084,828,081 bytes (2.87 GiB), inner zip 607 MB. Consistent.

Cross-check against the files, and against the paper (Table 2 on printed page 6, page image checked at 150 dpi; file-format text in section 5, printed pages 20-21):

1. Column order. Every file repeats the names in its own header (`columnNames.output`, and the `%` header lines of `gridPOrun.out`); the 31 names and their order match `columnNames_Details.txt`. Three 2015 Moon files (MoonA, MoonB, MoonD) have only the first 29 columns (no `x(1)-cross`, `x(5)-cross`). All 186 other files have 31.
2. Typo in the authors' list: `imag(b1)` appears twice. Column 12 is the imaginary part of b1 (horizontal), column 13 is the imaginary part of b2 (vertical). This is inferred from the pattern; the file never says so.
3. The paper's Table 2 lists only 11 items, not 31: Ncross, Dcross, Icross, M1rot, M2rot, T, J, (bv, bh), x0 and ydot0, x_perp2 and ydot_perp2, ra and rp. Name mapping to file columns: T = `period`; J = `JC-3` + 3 (see below); bh = `real(b1)`, bv = `real(b2)`; M1rot (rotations around the primary) = `Nrot`; M2rot (rotations around the secondary) = `Mrot` (the file letter is M for the secondary, N for the primary, the opposite of the paper's subscript order); x0, ydot0 = `x(1)`, `x(5)`; x_perp2, ydot_perp2 = `x(1)-cross`, `x(5)-cross`; ra, rp = `rAfar`, `rPfar`. The file also has columns the paper table does not list: `Ccross`, `shellCross`, `miss`, `stabA`, `x1byHR`, `Md`, `Nd`, `massratio`, the iteration ids, and the full 6-component state.
4. Paper says "A detailed list of the parameters and the data arrangement is described in a readme file, located in the top level folder" (p.21). In this tree that list is in `columnNames_Details.txt`; `README.txt` points to it.
5. Paper p.6 says the number of x-crossings Ncross is counted "from t0 to T/2"; the file text agrees. `Dcross` and `Icross` agree with Table 2. `Ccross` and `shellCross` exist only in the file text.
6. Frame and units (not stated in the column file or in Table 2; I checked numerically on Earth-Moon, Moon_L1_BPO row 1): all quantities are nondimensional CR3BP units (length = primary-secondary distance, time = 1/mean motion), `period` and states likewise. `x(1)` is measured FROM THE SECONDARY, not from the barycentre: the barycentric x is `x(1) + 1 - mu`. Check: with that shift, J = x^2 + 2(1-mu)/r1 + 2 mu/r2 - v^2 reproduces `JC-3 + 3` to 1.8e-15 over all 4830 rows. `x1byHR` = `x(1)` / R_Hill with R_Hill = (mu/3)^(1/3), reproduced to 1.3e-15. So `JC-3` is the Jacobi constant minus 3; velocities enter J as `x(4)` (vx) and `x(5)` (vy) in the rotating frame. Anyone who feeds `x(1)` straight into a barycentric integrator will be wrong.
7. `massratio` (column 6) is mu = m2/(m1+m2), constant within a file. The header's `muBODY1_km3s2, muBODY2_km3s2` give GM1 and GM2 and mu = GM2/(GM1+GM2) to every digit printed (checked on all 189 files, see `inventory_raw.tsv`).

### 4a. Mass ratios per system, against the project registry

The three agree to the printed 8 digits for all 24 systems, except the 2015 Moon files, whose mu is 5.6e-4 below Table 1.

Registry value: `cyclerfinder.core.cr3bp.cr3bp_system(primary, secondary).mu` (`src/cyclerfinder/core/cr3bp.py`). It uses mu = GM_secondary / GM_primary-system with JPL DE440 GMs from `core/satellites.py` (`PRIMARIES`, `SATELLITES`) and, for Sun-planet pairs, `core/constants.py` `PLANETS` with the IAU 2015 solar GM. Note the authors use GM1 = the primary alone (for the moon systems) while the registry uses the whole system GM as total, so small differences are expected. Sign: (registry - data) / data. - Sun-Earth, -1.2e-2: the authors' GM2 = 403,503 km3/s2 is the Earth-Moon barycentre system GM (paper Table 1 mu = 3.0404317e-6); the registry `PLANETS` Earth GM is Earth alone (3.986e5). Any consumer that seeds a corrector from a database orbit must use the file's own mu (column 6), not the registry mu, or re-converge. A mu shift of 3e-4 relative is large for sensitive orbits.

## 5. Loading one file in Python (numpy only)

Header lines start with `%`, the delimiter is whitespace. Tested on one real file (Earth-Moon, L1 BPO local search).

```python
import numpy as np
import os
ROOT = os.path.expanduser("~/dev/references/restrepo-russell-2018/POs_database_v2019-12-28/POs_database_all-2017-12-14")
path = ROOT + "/Earth_Sys/Moon/run20170518-194740_Moon_L1_BPO/gridPOrun.out"
NAMES = ["ithsol","it","JC-3","Md","Nd","massratio","x1byHR","miss","stabA","real_b1","real_b2","imag_b1","imag_b2",
         "x1","x2","x3","x4","x5","x6","period","rPfar","rAfar","Dcross","Icross","Ccross","Ncross","shellCross",
         "Mrot","Nrot","x1_cross","x5_cross"]            # 31 columns (the 2015 Moon A/B/D files have only the first 29)
a = np.loadtxt(path, comments="%")                         # header lines start with '%'; delimiter is whitespace
print(a.shape)                                             # (rows, 31)
print(dict(zip(NAMES, a[0])))
J = a[:, 2] + 3.0                                          # column 3 is JC-3
x0, vy0, T = a[:, 13], a[:, 17], a[:, 19]                  # perpendicular-crossing IC (x, y=0, z=0, vx=0, vy, vz=0) and period
print("mu =", a[0, 5], " J range:", J.min(), J.max())

# Frame check (independent of the file's own JC-3 column): x(1) is measured FROM THE SECONDARY.
mu = a[0, 5]
xb = a[:, 13] + 1.0 - mu                                   # barycentric x, primary at -mu, secondary at 1-mu
r1, r2 = np.abs(xb + mu), np.abs(xb - 1.0 + mu)
J_calc = xb**2 + 2*(1-mu)/r1 + 2*mu/r2 - (a[:, 16]**2 + a[:, 17]**2)   # planar: vx=x(4), vy=x(5); y=z=0
print("max |J_calc - (JC-3+3)| =", np.max(np.abs(J_calc - J)))
print("x1byHR check:", np.max(np.abs(a[:, 13] / (mu/3)**(1/3) - a[:, 6])))
```

- Pluto-Charon: NOT IN THE DATABASE. Table 1 and the folder list have no Pluto system. A Pluto lane must generate its own orbits, or use a different source.

Triton moves retrograde about Neptune in reality; the database is a generic planar CR3BP with prograde secondary motion and the files do not say how they treat that, so check sign conventions (Mrot, Nrot, x(5)) before comparing with our retrograde-Triton work.
